nixdisplay

Your displays, declared — and switched by what's plugged in.

Three Nix modules for a declarative Wayland desktop's screens: a fleet-wide monitor registry keyed by EDID identity (a panel roams between machines under one name), per-host output layouts with build-time overlap and positioning checks, and hotplug-reactive kanshi profiles that pick the arrangement from the set of connected outputs — the one thing a compositor's own config can't express.

Status: pre-alpha, real code moving to a new address

✓

Not new code — a new home for existing code

Every option here is the same module that has been the estate's monitor registry, output layouts, and dynamic-output daemon as nixdesktop's own modules/monitors.nix, modules/layouts.nix and home/kanshi.nix. It's moving out of nixdesktop, not being written from a blank file.

✓

Green flake check, on the parts a flake check can reach

nix flake check evaluates the two registries against fixtures and asserts every fired message: the identity string both compositors match on, and the logical rectangle an output occupies once its scale and transform are applied. The kanshi home-manager module is hand-verified — flake check never evaluates homeManagerModules at all.

!

The consumers aren't cut over yet

nixdesktop, nixscroll and the private host configs still reference the old nixdesktop.* namespace. Renaming their reads to nixdisplay.*, and enabling dynamicOutputs on the hosts that want it, is separate, deploy-gated work this page's existence doesn't imply is finished.

What it declares

A monitor registry, keyed by identity

nixdisplay.monitors.<slug> holds a panel's make/model/serial and any alias EDIDs, derives the "<make> <model> <serial>" string both niri and scroll match on, and asserts that no two declarations can ever resolve to the same one — the silent duplicate that attaches your workspaces to whichever panel enumerated first.

Layouts with arithmetic you can't check by eye

nixdisplay.layouts.<name> places each output by mode/modeline, scale, position and transform — and computes the logical rectangle each occupies to reject overlaps at build time. niri silently auto-places an overlapping output and logs one line; this catches it before it ships.

Profiles chosen by what's connected

nixdisplay.dynamicOutputs emits kanshi profiles from those same layouts. kanshi selects one by an exact cover of the connected heads, so "laptop panel off while docked" — a statement about the set of outputs, which no compositor config can make — becomes just another profile.

One owner per output, enforced by design

kanshi and the compositor both write output state, and the last writer wins (sway#6863, kanshi#43, niri#676). A host that turns on dynamicOutputs leaves the compositor's own layout unset. kanshi runs as its own graphical-session user service, declared here, borrowing nothing from a sibling's session layer.

Installs nothing, names no path

The registries touch no pkgs; the kanshi module writes one dotfile and a unit whose ExecStart is the bare name kanshi. The daemon is supplied by whatever puts binaries on the box — nixarch for Arch/CachyOS, or plain NixOS environment.systemPackages.

Reads nothing from its siblings

Its only flake input is nixpkgs. It owns the tables it reads, so unlike the compositor repos it needs no lib.probeFact mechanism at all. The repos that read it (nixscroll, niri, nixdesktop's session validator) do so defensively, without taking a flake input on it.

Get started

1. Add the flake input

inputs.nixdisplay.url = "github:julian-corbet/nixdisplay-corbet-ch";

2. Import the registries and declare your hardware

imports = [ inputs.nixdisplay.nixosModules.default ];

nixdisplay.monitors.dell = {
  make = "Dell Inc."; model = "DELL U4323QE"; serial = "9BQR2P3";
  nativeMode = "3840x2160@60";
};
nixdisplay.layouts.desk = {
  description = "one 4K panel";
  outputs = [ { monitor = "dell"; position = { x = 0; y = 0; }; } ];
};

3. Renamed from nixdesktop — no shim

The namespace moved from nixdesktop.{monitors,layouts,dynamicOutputs} to nixdisplay.*, matching this family's convention (the top-level attribute is always the repo's own name). Migrating means renaming every reference. No compatibility alias exists at this stage.

Where this fits

1. Displays — nixdisplay

Which panels exist, where they sit, and which arrangement applies when. Compositor-neutral: both niri and scroll read the same registry. Reads nothing back from either.

2. Compositor config — nixscroll / nixniri

Translates a named nixdisplay.layout into that compositor's own output blocks, resolving identity matches against nixdisplay.monitors — defensively, with no flake input on this repo.

3. Policy, session + chrome — nixdesktop

Which roles a session wants filled, the systemd session layer, and the compositor-agnostic pieces (bars, notifiers, lock). Validates a session's layout pointer against this repo's registry.

Roadmap (planned, not yet built)

Cut the consumers over

Point nixdesktop's session validator, nixscroll's translator, and the private host configs at nixdisplay.*, and delete nixdesktop's own copies of these three modules.

Enable dynamic profiles on the hosts that want them

The layouts for "laptop only", "external 4K", and "external 4K + pivot" already exist; turning dynamicOutputs on is a per-host, deploy-gated step.

A home-manager module check

The kanshi config generation and its user-service wiring are hand-verified today; a check that evaluates the module against a minimal home-manager stub would close the gap flake check leaves.
